# MCP로 만드는 원 인스턴싱 예제 요청

수업 TOE를 열고 로컬 STDIO MCP를 등록한 뒤 전문을 하나씩 복사합니다. 목표·조건을 AI에 설명하고 실제 결과를 확인하는 v6 요청문입니다. 구현 설정값은 AI가 기준 예제와 지원 도구를 읽어 정합니다.

## 01-connect.txt

```text
연결된 TouchDesigner를 MCP 도구로 확인해줘.
먼저 현재 프로젝트 이름·경로·TD 버전과 사용할 수 있는 도구를 읽어줘.
수업 프로젝트 AMG_MCP_Class_10x10.toe와 W05_REFERENCE_10X10 기준 예제가 맞는지 확인해줘.
연결 대상이 다르거나 도구 호출이 실패하면 만들기 전에 원인과 확인할 항목을 알려줘.
노드와 파일은 변경하지 말고, 확인한 대상과 다음 실습을 진행할 수 있는지 알려줘.
```

## 02-build.txt

```text
연결된 TouchDesigner에서 MCP 도구로 실제로 만들어줘.
현재 프로젝트와 지원 도구를 먼저 읽고, 기존 작업은 보존해줘.
새 실습용 Container W05_PROMPT_PRACTICE 안에서 작업해줘.
수업의 W05_REFERENCE_10X10 기준 예제를 확인하고 필요한 구조를 참고해줘.

1. 원
   1.1 배치: 같은 간격의 10×10 그리드, 총 100개. 위치는 고정해줘.
   1.2 색: 가장 큰 원은 흰색, 작아질수록 더 파랗게 보여줘.
   1.3 크기: 원마다 다르게, 노이즈로 부드럽게 커지고 작아지게 해줘.
   1.4 화면: 검은 배경, 정면, 기준 예제와 같은 화면 범위로 보여줘.

2. 실행
   구현 계획을 짧게 설명한 뒤 MCP로 노드와 출력까지 만들어줘.
   기준 예제에서 재사용한 부분과 새로 만든 부분을 알려줘.
   지원하지 않는 작업은 임의 코드로 우회하지 말고 가능한 범위를 알려줘.

3. 확인
   100개 위치와 인스턴싱, 색·크기의 관계, 시간 변화, 오류를 확인해줘.
   실제 출력과 만든 Container 경로를 보여줘.
```

## 03-check.txt

```text
MCP로 W05_PROMPT_PRACTICE를 검사해줘. 기존 기준 예제는 변경하지 마.

1. 위치: 10행×10열, 총 100개의 고정된 위치인지 확인해줘.
2. 색·크기: 시험용 복제에서 값을 0, 0.5, 1로 고정해 비교해줘.
   0에서는 원이 사라지고, 0.5에서는 작고 파랗고, 1에서는 크고 흰색인지 확인해줘.
3. 대응: 시험용 복제에서 왼쪽 위 한 셀만 바꾸면 같은 위치의 원만 반응하는지 확인해줘.
4. 시간: 서로 다른 세 시점의 출력을 비교해 크기와 색의 변화를 확인해줘.
5. 저장: 완성 Container를 TOX로 저장하고 다시 읽어 같은 조건의 출력을 비교해줘.
6. 정리: 실험용 복제와 보조 노드를 정리하고 완성본의 애니메이션을 유지해줘.

오류·경고, 실제 확인 결과, 저장 파일 경로와 확인하지 못한 범위를 알려줘.
```

## 04-build-20x20.txt

```text
MCP로 완성한 W05_PROMPT_PRACTICE를 참고해 새 Container W05_EXAMPLE_20X20을 만들어줘.
기존 작업은 보존하고 배치를 20×20, 총 400개의 원으로 바꿔줘.
화면 범위는 유지하고 원이 겹치거나 잘리지 않도록 기본 크기를 조절해줘.
노이즈로 색과 크기가 함께 변하는 관계는 유지해줘.
400개 위치·원 개수, 시간 변화, 오류·경고, TOX 저장과 재로드 결과를 확인하고 알려줘.
```

## 05-build-color-only.txt

```text

노이즈에 따라 파란색과 흰색 사이에서 색만 부드럽게 변하게 해줘.

서로 다른 세 시점에서 위치와 크기는 같고 색만 변하는지 확인해줘.
오류·경고, TOX 저장과 재로드 결과를 확인하고 알려줘.
```
