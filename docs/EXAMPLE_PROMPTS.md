# AMG_MCP 실습 프롬프트 — 복사·붙여넣기

배포 TOE를 열고 MCP를 등록한 뒤 순서대로 사용한다. 기존 AMG 1.0 / protocol 2, 포트 9987, 실제 Windows 검증 빌드는 TD 2025.32820이다. Mac은 네이티브 노드/TOP 기능으로 같은 요청을 사용할 수 있으나 실제 Mac 실행 검증은 미완료다.

AI에게 자연어 조건을 전달하면 AI가 라이브 노드와 파라미터를 읽고 지원 MCP 도구 호출로 구현한다. 이 MCP가 프롬프트를 스스로 해석하는 것은 아니다. 임의 Python/eval을 요구하지 않고, 현재 프로젝트 안의 검증된 네이티브 구조를 재사용한다.

| 단계 | 요청 파일 | 확인할 변화 |
|---|---|---|
| 연결 | [01-connect.txt](../prompts/01-connect.txt) | 프로젝트·Root·protocol·기능 |
| 제작 | [02-build.txt](../prompts/02-build.txt) | 위치 100개, 색·크기 함께 변화 |
| 검증 | [03-check.txt](../prompts/03-check.txt) | 값·개수·픽셀 대응·시간·재로드 |
| 확장 | [04-build-20x20.txt](../prompts/04-build-20x20.txt) | 400개와 20×20 이미지 대응 |
| 규칙 변경 | [05-build-color-only.txt](../prompts/05-build-color-only.txt) | 크기를 고정하고 색만 변화 |

아래 요청문은 각 코드 블록 전체를 복사해 사용한다. 제작 결과가 다르면 검증 결과를 함께 전달해 수정하도록 한다. 모든 AI가 같은 첫 시도 결과를 낸다고 보장하는 문서가 아니다.


## 01-connect.txt

```text
AMG_MCP로 현재 열려 있는 TouchDesigner와 연결 상태를 실제로 확인해줘.
td_begin_session으로 프로젝트명, Root, Bridge 경로, TD 빌드, AMG 버전, protocol, 지원 기능을 읽어줘.
수업 기준은 TD 2025.32820, 기존 AMG_MCP 1.0 / protocol 2, 포트 9987이야.
노드 생성·파라미터 설정·연결·CHOP 읽기·TOP 미리보기·오류 검사·TOX 저장/재로드 기능을 확인해줘.
capabilities의 operator_types에서 실제 생성 허용 노드도 읽어줘. TD 전체 노드 목록에 있다고 MCP가 그 노드를 생성할 수 있다고 판단하지 마.
현재 Root의 자식 노드를 읽고 기준 10×10 원 예제를 찾아줘. 프로젝트명과 경로를 먼저 보고해줘.
unknown_action: get_capabilities가 나오면 구버전 Bridge 연결일 수 있으니 제작하지 말고 오류와 설정의 포트를 알려줘. 설치 후 생성된 9987 설정과 현재 TD Bridge를 확인하도록 안내해줘.
Mac에서도 가능한 네이티브 노드 조작과 td_preview_top을 사용해줘.
이 단계는 읽기 검사만 하고 기존 노드, AI 설정, TOE는 수정하지 마.
```


## 02-build.txt

```text
AMG_MCP로 현재 TouchDesigner 프로젝트에 10×10 원 예제를 실제로 만들어줘.

1. 시작과 작업 범위
td_begin_session으로 현재 프로젝트·Root·protocol 2·지원 도구와 생성 허용 operator_types를 확인해줘. Root의 자식과 실제 파라미터 이름/메뉴를 읽어줘.
기준은 배포된 AMG_MCP_Class_10x10.toe의 10×10 예제야. 이미 열려 있는 원본 수업 파일에도 같은 구조가 있으면 사용할 수 있어.
기준 예제와 기존 Container는 보존하고, 같은 Root 아래 새 Container W05_PROMPT_PRACTICE에서 작업해줘. 이름이 이미 있으면 다른 이름을 사용하고 보고해줘.

2. 만들 화면
원의 위치는 XY 평면의 10행×10열, 총 100개로 고정해줘.
Grid 크기는 1×1, Circle 반지름은 X/Y 모두 0.05로 해줘.
원마다 시간에 따라 부드럽게 변하는 노이즈 값 v를 사용해줘.
색은 RGB=(v,v,1): v=1은 흰색, 낮아질수록 파란색 비율이 커지게 해줘.
크기는 Scale X=Y=v로 해줘. v=0이면 원이 사라지고 v=0.5이면 반지름이 절반이야. 위치 자체는 움직이지 않아.

3. TD 구조
Grid SOP → SOP to CHOP로 tx/ty/tz 각각 100샘플을 만들고 Geometry의 인스턴스 위치로 사용해줘.
Noise TOP은 10×10, Mono On, Amp 0.5, Offset 0.5, Period 1, Seed 1이야.
Noise TOP을 Geometry의 Scale OP와 Color OP에 직접 지정해줘.
Scale X=r, Y=g / Red=r, Green=g / Blue와 Alpha 채널은 빈칸으로 두고 기본값 1을 유지해줘.
Scale의 최소값을 0.4로 보정하거나 Math/Shuffle/Clamp를 추가하지 마.
정면 Orthographic 카메라 Width 1.1, 위치 (0,0,5), Light 위치 (0,0,10), 기본 재질을 사용해줘.
Render 1280×1280 → 검정 배경 합성 Transform → Out TOP으로 연결해줘.
노드는 입력→처리→출력 순서로 겹치지 않게 배치해줘.

4. 기존 AMG의 지원 범위
Geometry의 SOP 입력 커넥터 구조와 Noise의 시간식은 기준 예제의 geo1/noise1을 새 Container로 복사해서 재사용해줘. 나머지 노드는 새로 만들어줘.
복사한 geo1의 기존 외부 입력을 해제하고 새 circle1을 연결해줘. 위치·Scale·Color 참조는 새 Container 안의 SOP to CHOP/Noise로 다시 맞춰줘.
Noise Z의 시간×0.1 식은 복사된 것을 유지해줘. td_set_param으로 식 문자열을 넣지 말고, 지원되지 않는 Python/eval 기능을 추정하지 마.
기준 노드가 없거나 MCP로 구현할 수 없는 부분이 있으면 만든 것으로 보고하지 말고 정확히 알려줘.

5. 완료 검사와 저장
CHOP의 샘플 수와 실제 TOP 미리보기를 확인하고 오류·경고를 읽어줘.
노이즈 상태에서는 값이 0인 원이 사라질 수 있으므로 위치 100개와 화면에서 보이는 원 수를 구분해줘.
애니메이션 상태를 TOX로 저장해줘. 원본 TOE는 덮어쓰지 마.
생성한 Container, 실제 출력, 오류·경고, 재사용한 노드, 저장 경로를 보고하고 다음 검증 프롬프트로 확인할 수 있게 해줘.
```


## 03-check.txt

```text
AMG_MCP로 방금 만든 W05_PROMPT_PRACTICE를 실제로 검증해줘.
td_begin_session으로 현재 프로젝트와 대상 경로부터 확인해줘. 다른 이름으로 만들었다면 직전 제작 결과의 경로를 사용해줘.
기준 예제는 보존하고 새로 만든 실습 Container에서만 검사해줘. 먼저 현재 애니메이션 상태를 TOX로 저장해서 복구에 사용해줘.

1. 위치와 개수
SOP to CHOP의 tx/ty/tz가 각각 100샘플인지 확인해줘. 현재 CHOP 조회 도구는 전체 배열 대신 샘플 수와 첫 값만 반환하므로 그것만으로 전체 위치를 읽었다고 보고하지 마.
전체 위치 검사는 같은 실습 Container에 검사용 Math CHOP(Post-Add=0.5)와 CHOP to TOP(RGB, 100×1)을 임시로 만들고 SOP to CHOP → Math를 연결해서 수행해줘. 음수 좌표를 0~1로 옮긴 검사 이미지에서 고유 XY 100개, X/Y 각각 10개, Z가 0인지 확인해줘. PNG의 8비트 정밀도를 구분하고 검사 후 이 두 노드를 제거해줘. 최종 작품의 Scale/Color 흐름에는 이 Math를 넣지 마.
화면의 원 수는 별도로 확인해줘. 노이즈가 0인 원이 안 보이는 것은 위치 샘플이 누락된 것과 달라.

2. 값이 만드는 화면
Noise Amp=0으로 두고 Offset=0 / 0.5 / 1에서 각각 실제 TOP 이미지를 저장해줘.
v=0은 검은 화면, v=0.5는 반지름 절반이며 파란색 성분이 더 큰 원 100개, v=1은 기본 크기의 흰색 원 100개인지 확인해줘.
원 중심 RGB와 실제 지름을 비교해줘. 기본 조명 때문에 흰색 픽셀이 반드시 255인 것은 아니니 r≈g≈b인지도 확인해줘.
왼쪽 위 한 픽셀만 흰색인 10×10 시험 TOP을 만들어 Scale/Color에 임시로 지정하고, 같은 위치의 원 하나만 나타나는지 실제 출력으로 확인해줘.

3. 시간과 저장
시험 입력을 해제하고 Noise Amp 0.5, Offset 0.5와 시간식을 복구해줘.
약 1초 간격의 3장을 캡처해 위치는 유지되고 색·크기가 변하는지 비교해줘.
Noise Z=2.4로 고정한 출력을 저장하고 TOX로 내보낸 뒤 다른 새 경로에 재로드해 같은 Z=2.4 출력과 비교해줘. 다르면 참조/연결을 점검하고 수정해줘.
마지막에는 미리 저장한 애니메이션 TOX의 Noise를 새 실습 Container에 복사해 시간식을 복구해줘. 시험 노드와 검사 복제본은 정리하고 완성본을 TOX로 다시 저장해줘.

4. 보고
샘플 수, 원 수, 값별 중심 색과 지름 관계, 픽셀 대응, 시간 변화, 재로드 차이, 오류·경고, 최종 저장 경로를 알려줘.
실제로 이미지를 분석할 수 없는 항목은 미검증이라고 구분해줘. 실행하지 않은 검사나 Mac 실기를 통과했다고 보고하지 마.
```


## 04-build-20x20.txt

```text
AMG_MCP로 검증한 10×10 원 예제를 20×20으로 확장해줘.
td_begin_session으로 프로젝트·Root·지원 기능을 확인하고 W05_PROMPT_PRACTICE를 찾아줘. 없으면 먼저 10×10 제작·검증 프롬프트를 실행해야 한다고 알려줘.
기존 10×10은 보존하고 새 Container W05_EXAMPLE_20X20으로 복사해줘. 이름이 겹치면 새 이름을 보고해줘.

1. 화면 조건
XY 평면에 위치가 고정된 20행×20열, 총 400개의 원이야.
Grid 크기 1×1과 정면 카메라 Width 1.1은 유지해줘.
간격이 줄어드니 Circle 반지름 X/Y는 0.025로 바꿔줘.
Noise TOP의 해상도도 20×20으로 맞춰 원 400개에 값이 하나씩 대응하게 해줘.
색 RGB=(v,v,1), Scale X=Y=v, Amp 0.5, Offset 0.5와 원래 시간식은 유지해줘.
복제한 네트워크의 참조가 새 Container 내부를 가리키는지 확인해줘.

2. 실제 검증
tx/ty/tz 각각 400샘플을 확인하고 기본 예제의 위치 검증 방식으로 고유 XY 400개, X/Y 각각 20개를 확인해줘. 검사 이미지 해상도는 400×1로 바꾸고 같은 새 Container 안에 검사 노드를 둔 뒤 정리해줘.
현재 애니메이션 상태를 복구용 TOX로 저장하고 Amp=0, Offset=0/0.5/1에서 출력을 확인해줘. v=1에서는 흰색 원 400개가 보이고 원끼리 겹치거나 화면에서 잘리지 않아야 해.
0.5의 지름이 1의 절반이고 색의 Blue가 Red/Green보다 큰지 확인해줘.
복구 후 약 1초 간격 3장에서 색·크기 변화를 확인해줘.
Z=2.4의 고정 출력과 TOX 재로드 출력을 비교하고 시간식을 복구해줘. 검사 복제본은 정리하고 최종 TOX를 저장해줘.
원본 TOE는 덮어쓰지 마. 실제 위치/원 수, 오류·경고, 저장 경로, 미검증 항목을 보고해줘.
```


## 05-build-color-only.txt

```text
AMG_MCP로 10×10 원의 크기는 고정하고 색만 변하는 예제를 만들어줘.
td_begin_session으로 현재 프로젝트·Root·지원 기능을 확인하고 W05_PROMPT_PRACTICE를 찾아줘. 없으면 먼저 10×10 제작·검증 프롬프트를 실행해야 한다고 알려줘.
기존 실습은 보존하고 새 Container W05_EXAMPLE_COLOR_ONLY으로 복사해줘. 이름이 겹치면 다른 이름으로 만들고 알려줘.

1. 바꿀 규칙
10×10, 총 100개 위치와 Circle 반지름 0.05, 카메라/조명/렌더 설정은 유지해줘.
원의 위치와 크기는 고정해줘. Geometry의 인스턴스 Scale X/Y 채널을 빈칸으로 두고 기본 Scale 1을 사용해줘.
Color OP는 여전히 10×10 Noise TOP, Red=r, Green=g, Blue/Alpha는 빈칸 기본값 1을 사용해줘.
색만 RGB=(v,v,1)로 변하고 노이즈 시간식과 Amp 0.5/Offset 0.5는 유지해줘.

2. 실제 검증
애니메이션 상태를 복구용 TOX로 저장해줘.
Noise Amp=0, Offset=0/0.5/1에서 모두 같은 크기의 원 100개가 보여야 해. 색은 파랑→중간색→흰색이야. 기본 예제와 달리 v=0에서도 원이 사라지면 안 돼.
세 상태에서 실제 지름과 중심 RGB를 확인해줘.
복구 후 약 1초 간격 3장을 비교해 위치와 원 영역은 같고 색 픽셀만 변하는지 확인해줘.
Z=2.4에서 저장한 출력과 TOX 재로드 출력이 같은지 비교하고 시간식을 복구해줘. 오류·경고를 읽고 검사 복제본을 정리한 뒤 최종 TOX를 저장해줘.
기존 TOE는 덮어쓰지 말고 실제 검사 수치·저장 경로·미검증 항목을 보고해줘.
```
